| 16 | Coordinates in `mbingpdf/core` | PDF-native: origin bottom-left, y up. The top-left flip promised for the public API is done by the layer that paints the display list, not by the writer | 2026-11-10 |
| 17 | Text a font cannot show | `content.text()` throws, naming the font and character. Paragraph layout never throws: it falls back through the font list, draws the "missing" box, and lists the characters in `missingCharacters` | 2026-11-10 |
| 18 | Standard-font kerning | Not bundled (about 80 kB for a zero-config fallback). Kerning comes with embedded fonts | 2026-11-10 |
| 19 | Shaping reference | The built-in shaper's output must equal HarfBuzz for the test corpus; `harfbuzzjs` is a dev dependency used as the oracle | 2026-11-10 |
| 20 | Variable fonts | Instanced to a static font before embedding; instances are written without hinting (no `cvar` support) | 2026-11-10 |
| 21 | Line breaking and graphemes | Own implementation of UAX #14 and UAX #29 from Unicode 17 data, not `Intl.Segmenter`, so breaks do not depend on the runtime's ICU version | 2026-11-10 |
| 22 | Hyphenation | English uses the TeX en-US patterns (permissive notice licence). Indonesian uses our own rule-based syllabifier, because the TeX Indonesian patterns are GPL-2 and cannot ship in an MIT package | 2026-11-10 |
| 23 | Line filling | Greedy (first fit). Knuth–Plass optimal breaking can be added later without changing the API | 2026-11-10 |
| 24 | WOFF2 and Brotli | No Brotli decoder is bundled (its dictionary alone is 120 kB). `loadFont()` uses the runtime's own: `node:zlib` on Node, Bun and Deno, `DecompressionStream("brotli")` in browsers. `decodeWoff2()` accepts any decoder for runtimes with neither | 2026-11-10 |
| 25 | CFF fonts | Embedded as a CID-keyed CFF subset (`CIDFontType0C`). The subset keeps every subroutine rather than tracing which are used, so it is larger than HarfBuzz's; correctness first | 2026-11-10 |
| 26 | Font class name | One class, `Font`, for TrueType and CFF outlines (`loadFont()` also takes WOFF2). There is no separate `TrueTypeFont` | 2026-11-10 |
| 27 | Element call style | `Element(props?, ...children)`: properties are optional and children are variadic, so `Text("Hi")` works. Arrays of children are flattened and `null`/`false` skipped | 2026-11-10 |
| 28 | `size` on `Page` | Means the paper size. The default font size for a page is `fontSize`; everywhere else `size` is the font size | 2026-11-10 |
| 29 | Split boxes | A box split across pages is cut open at the split (no bottom border on the first part, no top border on the second) and its background runs to the page edge | 2026-11-10 |
| 30 | Unsplittable content | An image taller than a page is scaled to fit; a fixed-height box is clipped to the page; `keepTogether` is ignored for blocks taller than a page. Layout does not throw for these | 2026-11-10 |
| 31 | Image size without dimensions | 96 pixels per inch (1 px = 0.75 pt), as in CSS, shrunk to the available width | 2026-11-10 |
| 32 | Text in the SVG preview | Embedded fonts are drawn as glyph shapes, so the preview matches the PDF and needs no fonts installed. The 14 standard fonts have no shapes to draw and fall back to `<text>` in a similar system font | 2026-11-10 |
| 33 | Shaping speed | Each OpenType lookup keeps the set of glyphs it can start at, and `Font.shape()` caches results (4,096 entries). Layout of a 53-page report went from 2.2 s to 0.2 s | 2026-11-10 |
| 34 | Table cells and rows | A row is an array of cells; a cell is any child. `TableRow(props, ...)` and `Cell(props, ...)` exist for rows and cells that need properties. Column spans are supported, row spans are not | 2026-11-10 |
| 35 | Table lines | Not CSS border-collapse: a table has up to five kinds of line (outer, between rows, between columns, under the header, above the footer), set with `borders`. Lines take up space | 2026-11-10 |
| 36 | Text wider than its box | A word wider than its column is broken between characters rather than left to overflow | 2026-11-10 |
| 37 | Lists | A list item is one child; an item with several parts is wrapped in a `Stack` (a bare array is flattened into separate items, like any children). Items stay whole across pages unless `splitItems` is set | 2026-11-10 |
| 38 | QR quiet zone | `QrCode` includes the standard four-module quiet zone inside its `size` by default, so a code scans wherever it is placed | 2026-11-10 |
| 39 | Bleed | `Page({ size, bleed })`: `size` is the finished size and coordinates start at its corner. The page `fill` and `background` extend across the bleed; content is clipped at the bleed edge. Marks add 10 mm around the bleed | 2026-11-10 |
| 40 | Metadata | XMP is always written, uncompressed, alongside the information dictionary | 2026-11-10 |
| 41 | PDF/X-4 | Checked when the file is written: an output intent, a trim box on every page and embedded fonts are required, and the standard fonts are refused. No profile is bundled; the test profile is CC0 | 2026-11-10 |
| 42 | Headings | `Heading({ level })` sizes itself from the surrounding text (2, 1.5, 1.25, 1.1, 1, 0.9 times), stays with the next element, and becomes a bookmark and a table-of-contents entry unless `bookmark: false` | 2026-11-10 |
| 43 | Table of contents | Laid out in repeated passes until the page numbers stop changing (at most five); documents without one are laid out once | 2026-11-10 |
| 44 | Links within the document | Any element takes an `id`; `Link({ to })` points at it. Written as named destinations, so forward references work | 2026-11-10 |
| 45 | Columns | Filled one after another and balanced where the content ends; no spanning elements | 2026-11-10 |
| 46 | Long documents | `render()` writes each page to the file as soon as it is painted instead of holding every page's drawing list; documents with a table of contents are written again per layout pass. `layoutDocument()` still returns all pages | 2026-11-10 |
| 47 | Font instances | `font.instance()` returns the same object for the same style, so asking for "Bold" in every paragraph embeds it once | 2026-11-10 |
| 48 | Batch budget | 5,000 A5 bibs with fitted numerals and QR codes: under 60 s and 2.5 kB per bib as a test limit; measured about 10 s, 1.3 kB per bib and 300 MB of memory | 2026-11-10 |
| 49 | Themes | `defineTheme({ fonts, colors, text })` passed as `Document({ theme })`. Names are used directly: `style: "h1"`, `color: "brand"`, `font: "body"` with `weight` and `italic`. Type checking of the names is opt-in through `declare module "mbingpdf" { interface Register { theme: typeof theme } }` | 2026-11-10 |
| 50 | Theme conventions | The `body` text style is the document default; `h1`–`h6` style `Heading`. A style's `leading` (points) is kept as a ratio of the style's size. A font family is a variable font or a set of sources keyed by weight (`"400i"` for italic) | 2026-11-10 |
| 51 | SVG input | `Svg({ src })` reads paths, basic shapes, groups, transforms, solid fills and strokes, opacity and `<use>`, and draws them as vectors. Gradients, patterns, text, images, filters, clipping and masks are not read; a shape that depends on one is drawn plain or skipped. Checked against librsvg | 2026-11-10 |
| 52 | Shared graphics | Deferred from M3 to M4: no Form XObjects yet. Fonts and images are embedded once already | 2026-11-10 |
| 53 | JSX | `jsxImportSource: "mbingpdf"`. Element functions accept `children` as a property, so every tag is a plain function call; fragments and your own function components work; there are no lower-case intrinsic tags. `render()` and `inspect()` take any element and check at run time that it is a `Document` | 2026-11-10 |
| 54 | Diagnostics | `inspect(document)` returns each page's boxes as JSON-safe data rounded to 0.001 pt. Warnings carry the element path where the problem was first met. `strict: true` throws on the first warning. `debug: true` outlines every box | 2026-11-10 |
| 55 | Undefined properties | Any element property may be passed as `undefined` and is dropped when the element is built, so conditional properties need no spreading and an undefined value never overrides a default | 2026-11-10 |
| 56 | Bundle budget | `pnpm size` measures the gzip size of each entry point with everything it imports, untree-shaken, and fails CI when one exceeds `size-budget.json` (current size plus 10%). The whole document API is about 130 kB gzip; `mbingpdf/core` alone 31 kB | 2026-11-10 |
| 57 | Examples | Starter templates live in `examples/` as a private workspace package that imports `mbingpdf` by name; each exports a function from data to a document, plus sample data | 2026-11-10 |
| 58 | Release | Publishing is a manual step: the `Release` workflow is started by hand, defaults to a dry run, and needs the `NPM_TOKEN` secret. Packages are published with npm provenance. No source maps are shipped. Subpath imports need `moduleResolution` `node16` or `bundler` | 2026-11-10 |
| 59 | Preview components | `@mbingpdf/react` and `@mbingpdf/vue` each give `PdfPreview`, `usePdf` and `downloadPdf`, written without JSX or single-file components so they build with the same toolchain. Each page is shown as an `<img>` of its SVG (no script can run, no id clashes between pages), drawn when it nears the screen; links are real `<a>` elements laid on top. Both are built on `previewPages()` in `mbingpdf/svg` | 2026-11-10 |
| 60 | Link safety on screen | The SVG backend and the previews keep only `http`, `https`, `mailto` and `tel` links; anything else (such as `javascript:`) is dropped, because link addresses may come from user data. The PDF keeps every link as written | 2026-11-10 |
| 61 | Framework versions | React 18 or later; Vue 3.5 or later (for `useId`). `mbingpdf` is a peer dependency of both | 2026-11-10 |
| 62 | Preview server | `@mbingpdf/dev` gives the `mbingpdf` command (`dev` and `build`) and the functions behind it. A document file's default export is a Document or a function returning one; an `options` export goes to `render()`. The file is bundled with Rolldown (the package's one dependency) with packages left external, and the engine is imported inside that bundle so the tools and the document share one copy. The browser page is a single HTML file with no framework; it reloads through server-sent events and listens on `127.0.0.1` unless told otherwise | 2026-11-10 |
| 63 | Check order | `pnpm check` and CI build before testing, because the command-line tests run the built packages; without a build those tests are skipped | 2026-11-10 |
| 64 | Shared graphics | Every `Svg` is written to the PDF as a Form XObject: the same source in the same colour is stored once per file and only placed (moved and scaled) wherever it appears. No new element or option; artwork is recognised by its parsed shapes. The display list has a `shared` item for this, which the SVG backend turns into a `<symbol>`. Artwork is cut off at its viewBox, as SVG itself does. `Canvas` drawings and page furniture are not shared | 2026-11-10 |
| 65 | Benchmarks | `benchmarks/` is a private workspace package, run by hand and not in CI (one run takes minutes). Results are published as measured in `docs/benchmarks.md`, including where another library is faster | 2026-11-10 |
| 66 | Conformance option | `conformance` takes one standard or a list (`["PDF/X-4", "PDF/A-2a", "PDF/UA-1"]` is valid and tested). At most one PDF/A level. Requirements that cannot be met are errors when the file is written, as for PDF/X-4 | 2026-11-11 |
| 67 | PDF/A colour | Without an `outputIntent`, a PDF/A file declares sRGB. The sRGB profile is built from its published numbers in code (about 1 kB, no bundled file). With a CMYK or grey intent, RGB colours are read through sRGB as the page's default RGB space. CMYK or spot colours without a CMYK intent are an error: there is no neutral CMYK profile to assume. The intent must be a printer or display profile | 2026-11-11 |
| 68 | Tagged PDF is opt-in | `tagged: true`, or implied by PDF/UA-1 and PDF/A level a. Off by default because it adds an object per paragraph and cell (the sample files grow by about 10%) and most of our documents are printed. Revisit before 1.0 | 2026-11-11 |
| 69 | Structure from elements | The display list carries `tagged` items; paint wraps each box in its role and the PDF backend turns them into structure elements and marked content. Fragments of one element on several pages share the element (keyed by the source node, joined only when layout resumed it). Containers are transparent unless given a `role`. Shapes are artifacts except inside a figure; page furniture is a pagination artifact; a repeated table header or footer is an artifact on all but one page | 2026-11-11 |
| 70 | Pictures without a description | In a tagged file an `Image`, `Svg` or `Canvas` without `alt` becomes an artifact and raises the `missing-alt-text` warning (an error under `strict`). A `QrCode` defaults to `QR code: <value>`. Not an error, because a file with an undescribed decoration is still valid, and a wrong guess at a description is worse than none | 2026-11-11 |
| 71 | Line-break spaces | In a tagged file the space a line was broken at is written (invisibly, past the line's end), so text read from the structure keeps its word boundaries. A hyphen added by hyphenation stays an ordinary hyphen for now | 2026-11-11 |
| 72 | Validation | veraPDF is the judge for PDF/A and PDF/UA. The tests run it from a local `verapdf` or the `verapdf/cli` Docker image and skip when neither exists; CI sets `VERAPDF=required` on one job. Links now always carry the print flag, which PDF/A asks for and costs nothing | 2026-11-11 |
| 73 | Attachments and e-invoices | `Document({ attachments })` embeds files (`PdfDocument.attach` underneath); PDF/A-2 refuses them and PDF/A-3 takes them. `Document({ metadata })` adds described XMP properties. `facturX({ xml, profile })` returns both for a Factur-X / ZUGFeRD 2 invoice; the library neither writes nor checks the XML. XRechnung is left out until someone needs it | 2026-11-11 |
| 74 | Encryption | One scheme only: AES-256 with the PDF 2.0 standard security handler (revision 6), which Acrobat X and every current viewer read; the older RC4 and AES-128 schemes are not offered. SHA-256/384/512 and AES are written in TypeScript in `core/crypto.ts`, because `render.sync` cannot wait for Web Crypto; they are tested against Node's own. They live in the core rather than a separate entry point: about 6 kB gzip (4% of the library) is the price of a plain `encryption` option; move them behind their own import if the size budget gets tight. Random values come from `crypto.getRandomValues`; with `deterministic` they are derived from the passwords and content instead, which is for tests. Without an `ownerPassword` a random one is used that nobody knows. Reading for accessibility is always permitted. PDF/A and PDF/X refuse encryption | 2026-11-11 |
| 75 | Text on a canvas | `Canvas` gained `g.text()` and `g.measureText()`: one line, shaped with the fonts and size of the surrounding text, placed by `align`, `baseline` and `rotate`. No wrapping; text that must wrap belongs in a `Text`. This is what lets charts and barcode captions be plain canvases | 2026-11-11 |
| 76 | Barcodes | `Barcode` is a function that returns a `Canvas`; the patterns come from `mbingpdf/barcode` (under 3 kB gzip). Barcodes and charts add about 9 kB gzip to the whole root entry, but they are separate functions that a bundler drops when unused. Six symbologies: Code 128 (sets A, B and C chosen automatically; no GS1 FNC1 yet), EAN-13, EAN-8, UPC-A, Code 39, ITF and ITF-14. Check digits are computed, and a wrong one is an error. Values are validated when the element is made. Verified by decoding with zbar and ZXing in the tests (zbar in CI). 2D codes other than QR (Data Matrix, PDF417) wait for a request | 2026-11-11 |
| 77 | Charts | `BarChart`, `LineChart` and `PieChart` are functions that return a `Canvas`, so they need nothing from the layout engine and work in JSX. Deliberately small: grouped, stacked and horizontal bars; lines with gaps, areas and smoothing; pies and donuts; title, legend, round-number ticks, thinned labels. Areas are tints, not transparency, so charts stay valid in every PDF standard. The default palette is Okabe–Ito. Colours are resolved at draw time so that theme names work. No dual axes, no scatter, no log scale until asked for | 2026-11-11 |
| 78 | First adoption | One of the two apps moved its documents to the library before the first release, from the adoption guide and packed files, with its own agents; its notes drove rows 79–83. This is the practice for anything user-facing: try it in an app before publishing | 2026-11-11 |
| 79 | WOFF2 in browsers | Not supported: browsers give scripts no Brotli decoder (confirmed in Chromium; `DecompressionStream("brotli")` is refused), and bundling one costs about 50 kB for its dictionary. The guides say to use TTF or OTF, and how to unpack a WOFF2 once on a server. Revisit if a decoder becomes available or users ask | 2026-11-11 |
| 80 | Other image formats | `decodeImage` stays JPEG and PNG, read without the platform. `loadImage(bytes)` (asynchronous) hands anything else, WebP above all, to the browser's decoder through `createImageBitmap` and `OffscreenCanvas`; on a server it says to convert first. A WebP decoder of our own waits for demand from server-side use | 2026-11-11 |
| 81 | Vertical placement | `Stack` and `Page` take `justify`; a `Spacer()` without a size takes the spare height of a stack that has one, as it takes the spare width of a row. Only for a stack that is all on one page: content that breaks across pages flows as before | 2026-11-11 |
| 82 | Truncation and shrinking in a row | `Text({ truncate: true })` is one line ended with "…" (three dots if the font lacks the character). Text with `truncate` or `fit` reports the width it can shrink to, so a `Row` gives it what is left instead of overflowing. `maxLines` is left for later. `width: "auto"` and `height: "auto"` are accepted and mean "not given" | 2026-11-11 |
| 83 | Smaller additions from the same notes | `border.dash`; `Svg({ fit: "cover", monochrome })`; `usePdf(document, { lazy: true })` with `make()`; `PdfPreview` takes `pageLabel` and carries each page's text for screen readers (`PreviewPage.text()`) | 2026-11-11 |
| 84 | Content taller than a fixed height | A `Stack` with a `height` no longer holds its children to it: what does not fit sticks out below, as in CSS, and only the end of the page makes it break. Before, half a point of border was enough to send the last child of a box that fit on the page to the next one. Found in the adopting app's second round, with: the preview's text now includes pictures' descriptions (the preview is laid out tagged) | 2026-11-11 |
| 85 | Website | `site/` is a static site for mbingpdf.enterbiner.com, hosted on GitHub Pages (the owner chose it over the shared VPS: no load on it, no cold start) and deployed by `.github/workflows/site.yml` on every push to main. No framework: `site/build/generate.ts` writes the HTML, turns the repository's Markdown into the documentation pages, and has the library itself render the showcase documents (SVG, PDF, the hero's press sheet and the share image); Vite bundles the rest. The playground runs the library in the browser on plain JavaScript function bodies, the same files the generator renders. Look: a print shop (paper, ink, one spot colour, crop marks, the printer's colour bar), Barlow Condensed for display as in the studio's other work | 2026-11-11 |
| 86 | WebP of our own (replaces part of row 80) | The demand row 80 waited for came: the running-event app's server attaches receipts to e-mails and could not show the organiser's logo, which is WebP. A decoder of our own for lossy (VP8), lossless (VP8L) and lossy with alpha, in `mbingpdf/webp` (`decodeWebp`, about 18 kB gzip). `loadImage` reads WebP with it on every runtime, the browser included, so the server and the browser make the same file; it is loaded with a dynamic `import()`, so the root entry does not grow. It follows libwebp's own steps (edge samples, loop filter, "fancy" chroma upsampling, 14-bit YUV to RGB), and the tests require the exact pixels libwebp gives: 26 committed files cover both loop filters, segments, partitions, palettes of 2 to 200 colours, raw and compressed alpha and all three alpha filters, and Node, Deno, Chromium and a Web Worker check the same digests. The VP8 tables were read out of the installed libwebp, not typed. `decodeImage` and `Image` stay synchronous and JPEG/PNG only; animated WebP is refused; ICC profiles in WebP files are ignored | 2026-11-11 |
| 87 | A hyphen added at a line break (completes row 71) | The hyphen hyphenation adds is drawn as before but stands for U+00AD, the soft hyphen, in every file with embedded fonts (ISO 32000-1, 14.8.2.2.3 asks it of tagged files; it helps copying from any file). The font gives the glyph a second subset ID mapped to U+00AD, so a real hyphen elsewhere keeps U+002D. Readers leave soft hyphens out, so the word is read whole. Standard 14 fonts are unchanged: they cannot be used in tagged PDF/UA files, and their one-byte codes carry no text of their own | 2026-11-11 |
| 88 | Publishing through npm trusted publishing (supersedes the token part of row 58) | The `Release` workflow (still started by hand, dry run by default) publishes the packed tarballs with npm 11.5.1+ logging in through OIDC; each of the four packages on npmjs.com trusts `navis23/mbingpdf-engine`, workflow `release.yml`, with `npm publish` allowed. No token is stored: the `NPM_TOKEN` secret is deleted and the packages disallow token publishing. `actions/setup-node` gets no `registry-url` (its placeholder token blocks OIDC). Versions already on npm are skipped, so a re-run finishes a partial release. Provenance is automatic. First used for 0.2.0 | 2026-11-11 |
| 89 | Home page hero (owner's request) | No chips above the headline; the headline is at most 104 px (`clamp(60px, 6.4vw, 104px)`) so the hero breathes on desktop; phones keep 60 px | 2026-11-11 |
| 90 | Images stored at the size they are drawn | The running-event app's round 5 found that a decoded WebP is embedded at full size without loss: a 1600 × 900 logo drawn 40 pt high made a receipt 814 kB. `render` takes `maxImageDpi`: an image with more than twice the pixels it needs at that resolution is averaged down to it (area average, colours weighed by opacity so transparent edges stay clean). Opt-in, because a library that prepares files for press must not throw pixels away unasked; no default. Only where at least half the pixels go, so a nearly right image is not blurred for nothing and a flat PNG does not grow. Applies to raw 8-bit images and to PNGs stored as they came (inflated and unfiltered, palettes become RGB); JPEGs stay as they are (there is no JPEG decoder), as do 16-bit and packed grey images. One copy per image where the largest use comes first; copies are kept per render, never between renders, so the same document gives the same bytes. `minImageDpi` judges the image as given. `shrinkImage` is exported from `mbingpdf/image` | 2026-11-11 |

Decisions 8–10 and 16–58 were made by the plan's author under delegated authority and can be revisited: 8 if a customer or regulator asks for archival or accessible files, 9 when a print shop names a different profile.
